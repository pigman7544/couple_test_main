# PR #16 표시·가독성 실행 QA

검증일: 2026-11-09 (한국 시간). 대상: `feat/readability-ten-point-scores`, PR #15의 `0bc7c51` 위에 쌓인 PR #16. 병합·배포하지 않았으며 사용자 승인이 필요하다.

## 발견 및 수정

- 기존 `test_report_display`는 실제 리포트 구조에 맞아 최초 실행부터 통과했다. 그러나 표시 점수와 각 축 원점수의 정확한 대응, 반올림 경계, 브라우저의 실제 굵기까지는 검사하지 않았다.
- 전체 실행에서 c06 회귀 테스트의 `/100` 기대가 변경된 제품 요구와 충돌했다. `/10` 기대를 적용하되 원점수 구간별 해설·조언 독립 검사는 유지했다.
- Windows 기본 cp949로 HTML을 읽는 `test_v67.test_ui`가 실패했다. 파일을 UTF-8로 명시적으로 읽도록 수정했다.
- **브라우저 렌더러가 `◆ 제목\n본문` 전체를 `.subhead`로 감싸 본문까지 굵게 보이는 버그**를 발견했다. 이제 첫 줄만 소제목으로 감싼다. 제목 다음 중복 줄바꿈도 제거했다. 소제목·원전의 글자는 보존했다.
- 완성된 문장에 `/100` 정규식을 일괄 적용하던 방식을 없앴다. 세 리포트 작성 모듈이 공통 `report_display.ten_point_score(raw)`를 호출해 6축 제목을 만든다. 문학 원문 속 숫자나 점수 외 문장이 치환되지 않는다.

## 6축 데이터 흐름

`index.html → server.compute → engine.person × 2 → relationship_v08.relation → rel['vector'] → matcher.rank → narrative.describe → story_report.make_report`

이후 유형에 따라 `c01_report.enrich`, `c06_report.enrich`, `other_reports.enrich`가 실행된다.

| 장·출력 필드 | 원점수 키·순서 | 표시 경로 |
| --- | --- | --- |
| 3장 `saju_a` → DOM `sajuA` | attraction, security, growth | 유형별 paragraph/axis → ten_point_score → 제목의 정수 `/10` |
| 4장 `crisis` → DOM `crisis` | conflict, expression, autonomy | 동일 |

`personalized_reading.enrich`는 이 두 필드에 일상 해설을 추가한다. 마지막 본문 강조 정리는 점수를 바꾸지 않는다. 프런트엔드 `fill → renderProse`도 점수를 재계산하지 않는다.

해설·5장 조언·가상 장면은 **원점수**의 기존 `band(raw)`(45 미만 / 45 이상 65 미만 / 65 이상)로 선택된다. 표시값을 band나 matcher에 넣지 않는다. 원점수·rel 입력도 변이시키지 않는다. `engine.py`, `relationship_v08.py`, `matcher.py`, `couples.json`, `narrative.py`는 PR #15 기준에서 수정하지 않았다.

## 표시 척도와 2,400쌍 분석

고정 seed `20261109`, `audit_quality.payload`의 합성 입력 2,400쌍. 양력 1970~2004년, 월 1~12, 일 1~28, 시간 0~23, 무작위 성별이다. 실제 이용자·연령 대표 표본이나 임상 검증 자료가 아니다. 생성기를 두 번 실행해 입력 해시가 일치함을 확인했다.

입력 SHA-256: `db504ce4557b075c1afc41f2403ea3c73bcbca76c358dadeb21fa6d001b0a16a`

기존 PR의 `round_half_up(5 + (raw - 50)/7)`은 끌림 74.29%, 표현 63.33%가 한 표시값에 모였다. 단순 `/10`, 기존 7점 간격, 4점 간격, **선택한 5점 간격**을 같은 표본에서 비교했다.

선택: `clamp(ROUND_HALF_UP(4 + (raw - 50) / 5), 1, 10)`. 원점수 45→3, 50→4, 65→7이며 5 원점수당 표시 1단계다. Decimal 반올림으로 경계를 고정했다. 축별 백분위·별도 평균 보정 없이 모든 축에 같은 단조 변환을 적용한다. 이는 읽기 위한 편집 척도이며 원점수의 10분의 1이 아니다.

| 축 | 원점수 범위 | 원점수 평균±표준편차 | 표시 평균 기존→선택 | 신규 충돌률 기존→선택 | 선택 척도 10점 비율 |
| --- | --- | --- | --- | --- | --- |
| 끌림 | 50~81 | 58.08±5.42 | 6.19→5.67 | 43.88%→18.37% | 0.46% |
| 안정감 | 51.75~80 | 64.58±5.03 | 7.08→6.90 | 35.32%→25.76% | 0.50% |
| 갈등 | 46~85.2 | 59.16±7.93 | 6.26→5.78 | 18.53%→12.91% | 1.71% |
| 자율성 | 50~76.7 | 62.70±4.42 | 6.83→6.55 | 38.61%→27.40% | 0% |
| 표현 | 50.75~70.2 | 58.27±3.71 | 6.19→5.73 | 44.30%→32.39% | 0% |
| 성장 | 50~84.5 | 65.12±6.30 | 7.17→7.04 | 26.62%→19.21% | 2.96% |

충돌률은 전체 표본의 두 행 조합 `C(2400,2)` 중 **원점수가 서로 다르지만 표시값은 같은** 조합의 비율이다. 같은 원점수끼리의 원래 동점은 제외했다. 원래 동점률·전체 표시 동점률·원점수별 빈도·표시값별 원점수 범위·대안별 분포·성별 그룹별 요약은 [원시 분석 JSON](qa-display-2400.json)에 있다.

| --- | --- |
| 끌림 | 0, 0, 0, 186, 1011, 851, 171, 146, 24, 11 |
| 안정감 | 0, 0, 0, 1, 194, 696, 833, 523, 141, 12 |
| 갈등 | 0, 0, 125, 538, 378, 593, 402, 231, 92, 41 |
| 자율성 | 0, 0, 0, 20, 284, 813, 945, 306, 32, 0 |
| 표현 | 0, 0, 0, 77, 886, 1075, 327, 35, 0, 0 |
| 성장 | 0, 0, 0, 18, 284, 533, 699, 555, 240, 71 |

선택 근거: 6축 모두 기존보다 신규 충돌이 감소하고, 4점 간격 대안의 성장 10점 집중(32.67%)을 피한다. 단순 `/10`보다도 모든 축의 신규 충돌이 적다. 최빈값 집중은 끌림 42.13%, 안정 34.71%, 갈등 24.71%, 자율 39.38%, 표현 44.79%, 성장 29.13%다.

남는 한계·편향: 원점수 자체가 중상부에 몰려 있어 1·2점은 표본에서 나오지 않는다. 안정감·성장의 표시 평균은 여전히 상대적으로 높다. 축별 편집 규칙의 출발점·범위가 다르기 때문에 점수들을 같은 능력이나 좋고 나쁨으로 비교·평균 내면 안 된다. 특히 갈등은 높은 점수가 더 좋은 관계를 뜻하지 않는다. 표시 동점은 정수화의 필연적 정보 손실이며 없어졌다고 주장하지 않는다. 무작위 성별 그룹의 차이는 표본 구성 차이로만 보고, 인구집단 공정성의 증거로 해석하지 않았다. 같은 출생 입력에서 성별만 바꾸면 12종의 배역·본문·점수가 동일함은 별도 검사했다. 합성 표본의 백분위로 강제 균등 분포를 만들지 않았다.

## 실행 결과

- Python 3.11.9 / Windows: `python -X utf8 -m unittest discover` **37개 통과**. 기본 `test_v67` 포함. HTTP 입력·미리보기·언락·카드·과대 요청 검사가 포함된다. 첫 실행의 로컬 통신 권한 오류는 통신 가능한 실행 환경에서 재검증해 해소했다. 과거 보고된 Windows 연결 중단은 이번 최종 실행에서 재현되지 않았다.
- 12종의 5장 및 키 순서, 6개의 서로 다른 값이 올바른 축에 표시되는지, 0~100 단조성, 소수 경계, 클램프, 원점수 해설 선택, 입력 불변성, 본문 bold 제거·소제목/원전 글자 보존을 검사했다.
- 12종 × 시간 키 누락/빈 문자열/입력 × 성별 누락/여성·남성/남성·여성/other 조합을 통제된 유형 선택으로 검사했다. 같은 입력 반복 및 성별을 바꿨을 때 본문·배역 불변을 확인했다.
- 2,400쌍의 자연 선택 유형 리포트를 각각 두 번 생성해 완전 일치, 5장, 6축 표시값의 원점수 대응, 관계 입력 불변·전후 matcher 순위 첫 결과 불변을 확인했다. 자연 선택에서 4개 유형은 나오지 않았으므로 12종 전체 검사와 구분한다. matcher 자체는 수정하지 않았다.

- `node tests/test_c06_layout.cjs` 통과: 반복 유형 전환·장 제목·이름 조사·스크립트 구문 검사.
