# 12종 사주 해설 문체 QA

검증일: 2026-11-09 (한국 시간). 기준: PR #16 `bfc0922f31cca1acde29ef93aef7bf37c660ddcc`. 새 브랜치는 `feat/relationship-essay-voice`, PR base는 `feat/readability-ten-point-scores`다. 사용자 승인 전 병합·배포하지 않는다.

## 편집 결과

- 일간은 “나를 상징하는 사주 글자”로 소개하고, 계수(癸水)의 비와 이슬처럼 곧바로 이미지로 풀었다. 오행의 정의는 인물 소개에서 한 번 설명한다.
- 태어난 달을 읽는 기존 십성 선택은 유지하되 이름 목록 대신 약속·일정·돌봄·대화 장면으로 전달한다. 계산이나 배역 선택의 입력을 바꾸지 않았다.
- 개인화 모듈은 일간 이름과 오행 설명을 반복하지 않고 앞서 소개한 이미지에 기대어 말을 건넨다. 상생·상극은 둘의 조합에 해당할 때만 바로 설명하고 연락·약속 장면을 붙였다. 동일 오행에도 별도 해설이 있다.
- 2장은 원전과 문학적 해설을 전수 확인하고 보존했다. 3장은 일간 재소개를 줄이고 두 사람의 관계 비유를 보강했다. 4장은 이미 쉬운 관계 장면으로 작성되어 본문과 축별 해설, 개인화 가상 장면을 그대로 보존했다. 억지로 모든 문장을 다시 쓰지 않았다.
- 전문용어 20%/쉬운 해석 80%는 단어 수 검사에 사용하지 않았다. 길이보다 이해 가능성과 문학적 연결을 기준으로 검수했다.

## 전후 예시

기존 c06 인물 소개:

> 월간 甲을 일간과 비교한 십성은 편인이에요. 직관·독특한 관찰이라는 주제가 그 마음을 표현하는 방식에 색을 더해요.

개선:

> 태어난 달의 글자를 함께 읽으면 또 다른 표현 방식도 떠올라요. 바로 답하기보다 혼자 생각한 뒤 내 말로 설명하는 시간이 편할 수 있어요.

기존 개인화:

> 당신의 일간 계수: 여러 가능성을 두고 생각하는 모습으로 비춰 볼게요. 겉글자에서 많이 나타난 오행은 …에도 시선을 두게 해요.

개선:

> 당신에게 비춰 본 스며드는 비와 이슬의 이미지를 일상으로 옮겨 볼게요. 여러 가능성을 두고 생각하는 날이라면, 상대에게는 어떤 배려가 편한지 물어보세요.

상생 설명의 신규 예시:

> 전통 사주에서는 서로를 북돋는 흐름을 상생이라고 불러요. 비가 나무를 적시듯 한쪽의 힘이 다른 쪽에 닿는 비유예요. 연락이 뜸한 날 먼저 안부를 묻거나, 망설이는 계획에 응원을 건네는 장면을 떠올려 볼 수 있어요.

12종의 실제 생성 전후 인물 소개와 3·4장 전체 본문은 [전후 JSON](qa-essay-examples.json)에 있다. 원본 문장을 확인할 수 있도록 생략 없이 수록했다.

## 실행 검증과 보존 근거

- Python 전체 39개 통과: 기본 `test_v67` 포함. HTTP 입력·무료 미리보기·테스트 언락·카드, 결정론, 성별 및 출생시간 누락, 축별 구간과 조언 독립 검사를 포함한다.
- 신규 검사는 열 일간 × 열 일간의 100 조합 해설, 12종의 PR16 대비 원전·장 구조·미리보기·질문·조언·마무리·4장 전체 일치, 3·4장 축 점수와 축별 해설의 완전 일치를 검사한다. 원본 모듈은 `git show bfc0922`로 메모리에만 읽어 비교한다. 입력 불변성도 확인한다.
- Chrome 360/390/1440px에서 12종 × 3폭 = 36개 실제 렌더 통과. 5장, 정수 6축, 본문 강조 제거, 소제목 보존, 가로 넘침 없음, 페이지 오류 없음. c06 실제 입력→미리보기→언락→다시 입력도 통과했다. [렌더 결과](qa-essay-browser.json).
- 390px에서 12종 × 1~4장 = 48개 전체 장 캡처를 저장했다. `tests/qa-essay-<id>-390-ch<장>.png`. 각 장 상단을 모은 `tests/qa-essay-sheet-1.png`~`4.png`를 육안 검수했다. 긴 제목 줄바꿈은 정상이며 본문과 소제목의 굵기가 분리된다. 하단 전체의 레이아웃은 DOM 넘침 검사와 전체 장 캡처로 확인할 수 있다. 모든 실기기 검증을 의미하지 않는다.
- `node tests/test_c06_layout.cjs` 통과. 반복 유형 전환·장 제목·이름 조사·스크립트 구문 확인.
- `engine.py`, `relationship_v08.py`, `matcher.py`, `couples.json`, `archetypes.json`, `narrative.py`, `story_report.py`, `report_display.py`, `index.html`, `editorial_readings.py`, `individual_scenes.py`는 PR16 대비 변경 없음. c01/c06 TALE 및 보호 fixture도 변경 없음.
- 초기 제한 환경에서 로컬 HTTP 연결이 막혔으나 연결 가능한 환경에서 전체 테스트를 재실행해 통과했다. c06의 십성 이름·오행 나열을 요구하던 기존 문체 검사는 새 요구에 맞게 교체했고 나머지 회귀 검사는 유지했다.

## 재현

```text
python -X utf8 -m unittest discover
python -X utf8 tests/export_browser_reports.py
python -X utf8 server.py
node tests/qa_essay_browser.cjs
node tests/test_c06_layout.cjs
python -X utf8 tests/essay_contact_sheet.py
```

서버와 브라우저는 별도 터미널에서 실행한다. 필요하면 `PLAYWRIGHT_MODULE`, `BROWSER_PATH`로 로컬 Playwright 모듈·Chrome 실행 파일을 지정한다. 이번 검수는 기존 테스트용 가상 입력과 유형을 고정한 렌더를 사용했고, 12종 모두가 실제 기본 matcher에서 같은 입력으로 선택된다는 주장은 하지 않는다. 기존 f 계열의 “우정 원작을 연인 관계에 비추는” 방향은 그대로 두었다.
