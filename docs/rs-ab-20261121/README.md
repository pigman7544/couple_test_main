# 연연 RS 집필 비교 실험

2026-11-21 · 기존 합성 표본 3쌍 · 문서와 재현 도구만 별도 관리

**후속 시제품은 계산과 AI 집필을 결합하는 방식이 유리하다.** 세 쌍에서 검증된 계산을 공유하면서 B가 근거, 전통적 해석, 생활 장면을 더 구체적으로 이어 썼다. A는 같은 입력에서 같은 결과를 재현할 수 있고, 실제 서비스의 응답 경로도 갖추고 있다. 이번 B는 한 차례의 수동 AI 집필이며 자동 집필·검수, 지연, 비용, 실패 시 처리와 공식 RS 적합도는 미검증이다. 제품 구조 확정은 보류한다.

공식 RS는 사용자가 승인한 **「RS2 시제품 — 두 사람의 궁합」 전체 원고**다. 참조 대화에는 일부 문장과 설명만 있었고 [기준점 등록 문서](https://github.com/pigman7544/couple_test_main/blob/e1fbaeee27b25949c071ad72070a5a35771cebd0/BASELINES.md)에도 원문 첨부가 필요하다고 적혀 있다. B는 확인 가능한 ‘명리 근거 → 전통적 의미 → 관계 장면’의 흐름을 적용한 잠정 원고다. 공식 RS 충실도 점수는 보류한다. 저장소의 합성 기준 원고 5편은 공식 RS 원문과 구별했다.

## 실험 조건

- A는 [PR #32](https://github.com/pigman7544/couple_test_main/pull/32)의 **v1.4 궁합 미리보기 엔진**을 사용했다. PR은 2026-11-21 확인 당시 열린 초안이었으며 커밋은 `d08125d72d33a4440073c848a5dc598e25b0471d`였다. 기본 `main`의 레거시 서비스와 배포된 bone1은 실험 대상으로 선택하지 않았다.
- 기존 `evaluate_compatibility_v13.fixtures()`의 합성 24쌍을 실행했다. 표본 번호 01·02·04는 미확정 범위와 교차 구조가 다르도록 의도적으로 선정했다. 무작위 표본이 아니며 각 번호와 입력값은 원장에 있다. 3차 평가의 52.7%는 다른 엔진·표본에서 나온 과거 수치로 이번 결과에 합산하지 않았다.
- 두 방식에 같은 출생 입력과 같은 근거 범위를 사용했다. B는 A의 문단에 붙은 근거 ID의 합집합과 확인된 명식, 미확정 정보만 받아 새로 집필했다. A 문장 자체는 B 초안 작성 후 열어 대조했다. 계산·검증·집필·평가를 같은 작업자가 수행했다. AI 집필자를 별도 프로세스로 격리하거나 독립 평가를 실행하지 않았다.
- 계산 규칙 재대조는 엔진의 확정 명식에서 시작했다. 십성은 별도 오행 순환·음양 식, 지장간과 교차 작용은 별도 규칙표로 대조했다. 절기 시각과 날짜의 간지 자체에 대한 독립 역법 감수는 수행하지 않았다. 사주 상징을 실제 성격, 상대의 감정, 관계의 미래에 관한 확인된 관찰로 취급하지 않았다.

- **계산 오류 발견 0건(A·B 각각)**. 실제 원고에 명시한 일간, 위치, 한자, 십성, 합충형해를 원장과 대조했다. A의 일부 표현은 층위가 모호하고, 계산 ID가 붙어 있어도 바로 다음 조언까지 필연적으로 도출되는 것은 아니다. B도 가상 장면의 적합성을 입증하지 않았으며, 편재와 선택지 등은 전통 해석의 여러 읽기 중 이번에 고른 관점이다.
- **표본 간 완전 중복**. 장 제목과 공통 안내문을 빼고 문장부호 `. ! ?` 뒤 공백으로 분리했다. A는 66개 중 중복 문장에 해당하는 출현 12회(18.2%), 고유 문장 6종이었다. B는 68개 중 0회였다. 어휘나 의미가 비슷한 문장은 이 수치에 포함하지 않았다. B도 계산 근거를 설명하는 틀과 ‘살피는 단서’ 같은 표현은 반복된다.
- **편집 판정**. B는 세 쌍 모두에서 계산 근거가 장면과 실천으로 어떻게 이어지는지 더 쉽게 따라갈 수 있었다. 04에서는 A도 구체적인 장면과 행동이 있어 개선 폭이 상대적으로 작았다. 완전 중복 차이는 B의 세 편이 개별 집필되었다는 조건과도 관련된다. 대량 생성에서 같은 격차가 지속될지는 검증이 필요하다.

## 구조 판정

다음 시제품은 **확정 계산 → 근거 ID가 붙은 집필 입력 → AI 원고 → 계산 주장과 ID의 대조**를 권고한다. A의 근거 구조와 처리 경로를 재사용하면 계산 재현성을 지킬 수 있다. 원고의 근거 검사가 실패할 때에는 같은 입력에서 기존 템플릿을 쓰는 구조가 가능하다. 자동 B가 편집 통과율, 처리 시간, 비용 면에서 기준을 충족하는지는 별도의 미사용 표본과 독립 평가로 확인해야 한다. 이번 실험은 자동화 구현이나 상품 운영 전환을 포함하지 않는다.

## 검증과 재현

- GitHub에서 받은 RS 계산·글 생성 소스, 평가 표본 코드, matcher 및 데이터의 Git blob을 대조했다. Python 3.11.9와 기존 의존성을 사용했다.
- 세 쌍의 일간·천간 위치·십성·지장간 계층·교차 작용 및 A 근거 링크를 대조했다. 실서버 연결은 이 환경에서 Windows 소켓 권한 오류가 나서, 실제 요청 처리기의 POST 메서드를 메모리 요청으로 호출했다. 세 쌍에서 `/api/compatibility/preview`와 `/api/compatibility/report` 응답 총 6건, 전체 문단과 미리보기 발췌 일치를 확인했다.
- 호환성 v1.1~v1.4 및 v6.7 로컬 테스트 **25개 통과**. 첫 실행에 정적 HTML과 이미지 두 장이 빠져 2건이 실패했으며, 기존 제품 스냅샷의 파일을 격리 폴더에 갖춘 뒤 재실행했다. v6.7 보조 코드는 로컬 제품 스냅샷을 사용했다. 실제 배포 환경과 브라우저는 재검증하지 않았다.
- 실험 브랜치를 체크아웃한 저장소 루트에서 기존 의존성을 설치한 뒤 아래 명령을 실행한다. 이 명령은 실험 자료 경로에 A 전문·근거를 다시 작성하고 메모리 요청과 문장 중복을 확인한다.
